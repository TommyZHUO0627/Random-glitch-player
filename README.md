BUFFER / LOOP · 随机故障音乐播放器

English

把网络卡顿，变成意外的节奏。

为什么做这个播放器？

本播放器的灵感产生于听歌时网络卡顿的意外体验：最近几秒反复循环，有时竟产生有趣的节奏。

我想把这种偶然发生的体验变成一个可以主动尝试的小工具：导入自己的歌曲，让播放器随机重复刚刚播放过的片段，听听熟悉的音乐会产生什么意想不到的变化。

功能

随机重复最近的音频，默认片段长度为 0.5–3 秒。

自定义故障间隔、片段长度和重复次数。

支持自动触发、手动触发和提前恢复。

支持播放暂停、进度调整、音量控制和实时频谱。

根据浏览器语言显示中文或英文，也可手动切换。

无需安装，本地 HTML 可离线使用。

如何使用

下载本项目并解压。

用浏览器打开 index.html 或 random_glitch_player.html。

点击「选择歌曲」，导入本地音频。

点击「播放」，开启「自动随机触发」，或点击「立即卡顿」。

也可以通过本项目的 GitHub Pages 网页使用，无需下载播放器。

快捷键：空格播放或暂停，G 立即卡顿，R 恢复正常。

音乐会上传吗？

不会。音乐文件只在当前设备的浏览器中读取和处理，不上传至 GitHub 或其他服务器。

GitHub Pages 只负责提供播放器网页。每位使用者自行选择本地歌曲，刷新页面后需要重新导入。

工作原理

发生故障时，播放器冻结原曲进度，重复播放当前位置之前的一小段音频。重复结束后，从被冻结的位置继续播放。

这是一种模拟网络卡顿的音频效果，不需要真的断开网络。

支持与限制

支持 MP3、WAV、M4A 等浏览器能够解码的格式。

建议使用较新版本的 Chrome、Edge 或 Safari。

长音频可能占用较多内存。

手机锁屏或切换后台可能导致播放暂停。

不支持直接处理 Spotify、Apple Music 等受保护串流。

部署到 GitHub Pages

将项目文件上传到仓库根目录，确保其中包含 index.html。

打开仓库的 Settings → Pages。

选择 Deploy from a branch。

选择 main 分支和 /(root)，点击 Save。

部署完成后，打开 Pages 页面提供的网站链接。
