# BUFFER / LOOP · 随机故障音乐播放器

[English README](README.en.md)

导入本地歌曲，随机重复刚播放过的片段，模拟网络卡顿形成的意外节奏。纯静态、单文件、无依赖，无需安装或构建。

## 中文 / English 界面

首次打开会根据浏览器的首选语言显示界面：中文（包括 大陆地区、港澳台地区）显示简体中文，其余语言显示英文。页面右上角可随时点击「中文 / English」，介绍、按钮、说明、播放状态及日志会一起切换，不中断音乐播放。

选择的语言保留在当前网址末尾，不使用 Cookie 或浏览器存储。可以分享固定语言的链接，例如 `index.html#lang=zh`、`index.html#lang=en`；GitHub Pages 的首页链接也可以直接加 `#lang=en`。翻译全部包含在 HTML 中，离线可用。

## 在电脑上播放

1. 下载本项目并解压，使用 Chrome、Edge 或 Safari 打开 `index.html`。
2. 点击「选择歌曲」，选择电脑上的音频，然后点击「播放」。
3. 保持「自动随机触发」开启，或点击「立即卡顿」手动触发。
4. 「恢复正常」会提前结束重复，从卡顿点继续播放。

`random_glitch_player.html` 是与 `index.html` 内容相同的便携副本，可单独复制到其他电脑并离线使用。以后修改时，请同步两个文件。

默认抓取 0.5–3 秒，重复 2–6 次；自动故障在正常播放期间约每 6–14 秒触发一次。故障期间原曲进度冻结，重复结束后继续。开头尚无足够音频时不会立即触发。可调整间隔、片段长度和重复次数。

支持暂停、拖动进度、音量、频谱、故障日志。快捷键：空格播放/暂停，G 立即卡顿，R 恢复正常；焦点在按钮或输入框时保留控件自身的键盘操作。

## GitHub 与本地音乐的区别

| 使用方式 | GitHub 提供什么 | 歌曲在哪里 |
| --- | --- | --- |
| 本地打开 HTML | 无需 GitHub 或网络 | 浏览器读取你选择的本地文件 |
| GitHub 仓库 | 保存和分享播放器源代码 | 不需要放进仓库 |
| GitHub Pages | 托管播放器网页，提供访问链接 | 仍由每位使用者自行选择本地文件 |

**选择歌曲不是上传歌曲。** 程序通过 `File.arrayBuffer()` 和 Web Audio 的 `decodeAudioData()` 在浏览器内存中读取、解码音频。没有上传 API、分析服务、远程字体、CDN、Cookie、LocalStorage 或 Service Worker，也不会保存歌曲。刷新页面后需要重新选择文件。文件名及日志只在当前页面显示。

页面包含内容安全策略，禁止网络连接（`connect-src 'none'`）和表单提交。通过 Pages 打开网页时，浏览器仍需向 GitHub 请求网页本身；网站托管服务可能记录网页访问。这与上传音频是不同的。本地双击 HTML 不依赖网络。此保证适用于本项目提供的代码；自行添加第三方脚本后应重新检查。

## 发布到 GitHub

项目已准备好，但没有创建仓库、推送提交或启用 Pages。

1. 在 GitHub 新建仓库，例如 `random-glitch-player`。
2. 将本目录中的文件上传到仓库根目录，包含 `index.html`、`random_glitch_player.html`、`README.md`、`README.en.md`、`LICENSE`、`.gitignore` 和 `.nojekyll`。不要把外层文件夹作为唯一目录上传，否则首页不在根目录。
3. 选择 **Settings → Pages → Build and deployment → Source → Deploy from a branch**。
4. 选择保存文件的分支（通常为 `main`）及 **/(root)**，点击 **Save**。
5. 等部署完成，在 Pages 设置页打开生成的链接。通常形如 `https://你的用户名.github.io/random-glitch-player/`。

无需 npm、构建命令或自定义工作流。部署方式参见 [GitHub 官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。公开仓库可使用 GitHub Free 的 Pages；其他仓库的可用性依账户方案而定。

不要向仓库添加私人歌曲。`.gitignore` 默认排除常见音频格式与音乐目录，但它不能阻止网页手动上传，也不会移除已被 Git 跟踪的文件。

## 支持与限制

- MP3、WAV、M4A、AAC、Ogg、FLAC 等能否播放取决于浏览器和编码格式；解码失败时可尝试普通 MP3 或 PCM WAV。
- 整首音频解码到内存，长录音可能占用较多内存；解码后的体积可能远大于原文件。
- 手机文件预览器可能无法运行 HTML；请用完整浏览器。后台、锁屏和系统节能机制可能暂停音频或延迟界面与自动触发计时。
- 不能直接播放 Spotify、Apple Music 等受保护串流。本项目不包含歌曲，也不会导出混音。
- 循环边界使用短淡入淡出减轻爆音，但随机切片仍可能出现明显的音色跳变。
- 在线页面首次打开需要网络；要可靠离线使用，请下载 HTML，而非依赖网页缓存。

## 检查本地处理

可打开浏览器开发者工具的 Network 面板，清空请求列表后导入并播放歌曲，观察没有音频上传请求；通过 Pages 打开时请区分初次载入网页的请求。断开网络后，本地 HTML 仍可导入并播放。项目没有服务端组件。

整理版本已在 Windows 的 Edge 无界面浏览器中用生成的 12 秒 WAV 检查：实际解码、播放暂停、手动和自动卡顿、自动及手动恢复、拖动进度、连续选歌、无效文件后重新导入、歌曲结束及重新播放。未出现页面脚本异常，页面请求仅有本地 HTML；另检查了 390 像素视口下的布局。未对所有浏览器、编码格式和移动设备进行实机听感测试。

双语版另外检查了浏览器中英文首选语言识别、播放期间切换语言、文件名及参数保留、日志翻译、网址语言选择在刷新后保留，以及英文手机宽度布局。
